Where business intelligence lives

00:05:49 The first question asked which two stages of the analytics journey business intelligence lives in, and the answer is pre-analytics and descriptive. The point of BI is to pull data, typically from several sources, and put it in front of people as an interactive dashboard so they can ask their own questions. The Job Scout example from Class 01 was both halves at once: scraping job ads, organizing them, and putting them in a readable table in a database is the pre-analytics part; the interactive charts on top, where you can ask for jobs in Ohio that want Tableau and Power BI, are the descriptive part. The data management piece is the work you did in 345. What this class adds is pulling data from sources outside your own organization.

00:07:24 Descriptive analytics itself splits in two: statistical summaries of the data, and visualizations people can understand. Predictive analytics is typically machine learning. Prescriptive got two buckets. One is experimental design, the sort of thing you would do in ISA 335: if Amazon moves its buy button to a different place and runs an A/B test, do more people buy? The other is the optimization side from ISA 321. You might have a good predictive model of how stocks will do over six months, but that does not mean you put all $10,000 in one of them. You want to maximize return while minimizing risk, which means deciding how much of the $10,000 goes into each stock.

00:08:55 BI is associated with dashboarding above all: generating insights from a dashboard in Tableau or Power BI, either retrospectively (how did we do last quarter) or in real time (in the Ford plant up in Michigan, what are we producing right now).

Three shapes of data

00:10:13 The second question was the JSON one, and the room did better on it. The three buckets, in the order the Job Scout example produces them: the wall of text describing a job is unstructured, because text and images are not structured by design. The skills that come back from the job-ads API arrive as JSON, and for a given job you might have ten skills. That is more organized than free text, but to put it in a data table you still have to decide how. Do you compress all the skills into one cell separated by commas or semicolons? Or do you build a long table with a job ID and a skill, so a job with five skills is five rows and a job with fifteen skills is fifteen rows? That decision is yours to make, and having to make it is what semi-structured means. Structured data is what you handled in 345: anything that already sits in a data table, the nice CSV you consume when you run a regression.

Data encoding, and why color is not encoding the counties

00:12:52 The third question showed the county-level map and asked how the counties are encoded. This one drew a pause, and Fadel used it to re-state two terms from Class 01.

00:13:13 The first is the unit of analysis: what does one row of data mean? In the crash dataset the unit of analysis was not a crash, it was a person involved in a crash. The second is data encoding, which is a fancy way of asking how a variable in your file gets represented in a picture. On this map the counties are drawn: the x and y position on the map traces the border. Butler County sits where it does because it is in southwestern Ohio, next to Montgomery and Warren.

00:14:35 So why is color not the encoding for counties? Because color is not being used to tell Butler from Warren. The New York Times used color for the case count per capita: light orange means few cases, dark red or maroon means many. Nobody is saying Warren is orange and Cuyahoga is green as a way of telling them apart. Color encodes the case rate, not the county identity. Fadel checked twice that this had landed, noting the recording is there for it.

Commit, push, pull

00:15:43 The fourth question: you edit a file, save it, and commit it. Where does that file live now? The room got this one wrong enough that Fadel took it as an invitation to ask more questions in class.

00:16:21 Git and GitHub are different things, and Git operations happen on your computer. Ticking the checkbox in GitHub Desktop means you want to track a particular file. Clicking commit means you want a snapshot of that file as of 8:46:59 a.m. on August 31st. That is the equivalent of naming a version in a Google Doc history: this is the version I want to track, and if everything worked up to that point, this is the version I can come back to.

00:17:13 So for everyone who answered that the file is now on every computer where you are signed into GitHub Desktop: not yet. Committing does not put anything on the server. That is the push operation. And to have the file on a second computer you need two things: that you pushed it, and that you pulled the latest version of the repository onto that other machine. Pushing means it is on the cloud server at github.com, nothing more. If you want your laptop, or a gaming machine at home, to match your M drive, you open GitHub Desktop on that machine, go to the repository, and pull. Every other computer needs its own pull.

00:18:32 A note that sets the tone for the rest of the session: this is not a sprint. If the room needs something explained in more detail, it gets explained in more detail.

Which files can Git diff

00:18:58 The fifth question: for which file can Git show you exactly which lines changed?

00:19:21 Wednesday’s slide split files into two colors, binary and not binary. Fadel could not recall which color went with which and said so. Binary files are things like a Word document, an image, a PDF. For those, Git can tell you the version changed, but not line by line what happened. For a Markdown file, a text file, a CSV (not an Excel file, a CSV), an R file, a Python file, anything flat, Git can tell you exactly what you changed. That is what we saw on Wednesday when a line was added to the skills list in the Markdown document: Git showed there was no line here before, and now there is one. Edit a line and it shows the old line and the new line side by side. With a .docx, a .png, or a PowerPoint, Git can save the prior version, but all it can tell you is that the new version differs, not how.

Undo versus revert

00:21:09 The last question: you pushed a commit with a mistake in it. What is the fix that keeps the history honest? Fadel asked the room to take the sentence apart first.

00:21:34 You pushed a commit, which is two things: you took a snapshot of the version containing the mistake, and you sent that snapshot up to GitHub. The mistake is already on the cloud. To keep the history honest you say: I made a mistake, that was version 2, and version 3 is going to be the state of things before the mistake. So the history reads as what you started with, then the mistake, then a new version that undoes it, with every step still visible. The term for that is reverting.

00:22:47 The other options do not work. There is no real undo in GitHub Desktop once you have pushed. Deleting the repository and starting over, which nobody picked, loses the history entirely. And pulling the latest repo from github.com just brings the mistake down to another computer, because the mistake is what is up there.

The YAML header

00:40:37 The block between the two rows of three dashes, lines 1 to 6 of a new file, is the YAML, which stands for Yet Another Markup Language. Fadel hedged that the one-line gloss may not be fully accurate, but that as a mental model it is good enough: this is where you specify the metadata and how you want the file to look. Out of the box, clicking Knit produces an HTML file that lands next to the .Rmd, in markdowns/.

00:41:31 A small typing habit worth stealing: YAML is whitespace-sensitive in a way R is not, so instead of counting spaces, type the key and its colon first, then press Enter. RStudio indents the next line for you. Fadel deliberately wrote html_document: with the colon before pressing Enter to show the automatic indent.

00:42:14 From there the header gets built up one option at a time, knitting after each to show what changed. toc: TRUE adds a table of contents at the top of the document, which on the template file listed R Markdown and Including Plots.

00:42:52 toc_float: TRUE moves the table of contents to the left and makes it follow you as you scroll, which is what you want for the long documents you will end up writing. 00:43:26 number_sections: TRUE numbers the headings, so the two template sections become 1 and 2.

00:44:18 code_folding: show works only in HTML documents and does two things: a Code button appears at the top right of the knitted page with Show All Code and Hide All Code, and each chunk gets its own show/hide toggle.

00:44:48 code_download: TRUE is the one Fadel uses so that only one file has to be handed out. With it set, someone who has only the HTML can download the .Rmd from the page itself.

Debugging the YAML in the room

Part 2: Objects and vectors

Three assignment operators

00:59:05 R is a weird programming language in one specific way: you can assign a value to an object in three different ways.

#| eval: false
1crashes_per_day = 30125 / 365
2crashes_per_day <- 30125 / 365
330125 / 365 -> crashes_per_day
1
=, which is what you have most likely used in your other classes and what we use here.
2
<-, literally an arrow: take this value and assign it back into the name. This is what you get if you ask ChatGPT for R code or find code online, and it was the default way people wrote R, Fadel guessed, ten or fifteen years ago.
3
->, pointing the other way. Uncommon, but Fadel does use it at the end of a series of piped steps, where saying “and the output goes into this object” reads well.

01:00:13 All three do the same thing. Fadel did not know whether other languages offer this and said so; the point is only that R has three and that this is unusual.

Object not found

01:00:13 R’s errors are awful. They are not very descriptive. The most common one you will meet is object ... not found, and Fadel simulated it live by deleting crashes_per_day from the environment with rm() and then pressing Ctrl + Enter on the line that prints it. R has no idea where the object is and cannot help you.

01:01:11 That single message has three causes, and Fadel’s ranking of them: you capitalized something that should not be capitalized, you have some other typo in the name, or you simply never ran the line. The easiest way to check is to look at whatever you wrote and then look at the Environment pane. If it is not there, that is why you are getting the error.

R is a vector language

01:01:38 The interesting thing about R is that it is a vector language: you can run a function on a whole vector and it works, element by element, without you writing a loop. The seven numbers used here are the counts of crashes on each day of the week in 2025, the same seven bars from Wednesday’s chart.

#| eval: false
1crashes_by_day = c(2020, 2241, 2327, 2285,
                   2380, 1866, 1664)
2names(crashes_by_day) = c("Mon", "Tue", "Wed", "Thu",
                          "Fri", "Sat", "Sun")
crashes_by_day
3crashes_by_day > 2000
4sum(crashes_by_day > 2000)
5mean(crashes_by_day)
1
c() puts the numbers together into a vector of seven elements. Fadel thinks of it as concatenating, while noting that whether that is technically what is happening is another matter.
2
names() attaches a name to each element, making it a named vector. Printing it now shows Mon at 2020, Tue at 2241, and so on.
3
A greater-than sign in R is a logical operation: it asks, for each element, true or false. One comparison, seven answers. On the slide, Saturday and Sunday come back FALSE and the other five TRUE.
4
sum() of TRUEs and FALSEs counts the TRUEs, because TRUE is 1 and FALSE is 0. The slide shows 5.
5
mean() works on the vector the same way, and the slide shows 2111.857.

01:03:36 No for loop anywhere. Fadel’s contrast: in Python the default way to do this would be to go through the list, typically with a list comprehension. In R you operate on the vector itself.

Types

01:04:22 R has six data types by default, four of which are common enough that this class will highlight them. Logical is just TRUE or FALSE. Integer is a whole number, and to make something an integer in R you give it an uppercase L.

01:04:48 The demonstration was a bit of a fumble over which object was called what, which is worth watching for its own sake: Fadel had to go back, check the name in the earlier chunk, and copy it rather than retype it. Under a new heading, ## Type of `crashes_per_day` (the backtick is the key next to the 1, and it makes the name render as code when you knit), the second chunk of the class RMD is:

#| eval: false
1typeof(crashes_by_day)

2crashes_by_day_int = c(2020L, 2241L, 2327L, 2285L,
                   2380L, 1866L, 1664L)
3names(crashes_by_day_int) = c("Mon", "Tue", "Wed", "Thu",
                          "Fri", "Sat", "Sun")
4crashes_by_day_int |> typeof()
1
In the console this returned "double".
2
The same seven numbers, copied from the chunk above rather than retyped, with an uppercase L after each one to make them integers. Fadel said out loud not to type these by hand.
3
Copying the block over left this line still naming crashes_by_day; Fadel spotted it and changed it to crashes_by_day_int, adding that it did not really matter here, because the only thing being checked was the type.
4
The native pipe: take the thing on the left and make it the first input to the function on the right. Ctrl + Shift + M types the pipe. This returned "integer".

01:09:31 The pipe is unnecessary here and Fadel said so; it was shown only to show it. The substance is the contrast between the two: the first vector had no decimal points anywhere and R still stored it as a double, because a double is what allows decimals. If you want something to be explicitly an integer, you have to tell R.

Four types, and the trap

01:10:45 Back to the slides for a visual view of the four types. Logical takes two values. Factor is the one you have met in regression: if you had days of the week as a predictor, you made them a factor. A factor is another way of saying categorical variable, and it differs from a character variable in that it is limited to specific values. If the days of the week are Sunday, Monday, Tuesday, Wednesday, then those are the levels, and you cannot have a day of the week called something else. That is the point of it: you specify the levels the variable is allowed to take. Fadel’s analogy was a select filter in a dashboard, which limits people’s answers to a fixed list.

01:12:07 Integer and double are the numeric types. Fadel misspoke and immediately corrected: double allows decimal points, integer does not.

01:12:33 To check the type of something, typeof(), and you can hand it a single value or a whole vector.

01:16:39 That is the rule worth carrying out of today, and it is not only an R rule: a vector can hold only one type. Mix types in it and R generalizes to the most general type that can hold everything. Integers and doubles together, say 401L and 44.7, generalize to double, because a double can represent both. Numbers and text together generalize to character.

01:17:14 So in the table on screen, age shows 47 in one row and a letter code in another, and that makes the column character. latitude_x obviously has a decimal point, so it is a double, and injuries is obviously text.
